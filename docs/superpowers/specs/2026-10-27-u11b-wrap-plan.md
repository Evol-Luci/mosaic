# U11b — multi-line and word-wrap: slice plan

**Date:** 2026-10-27
**Parent:** [U11 decomposition](2026-10-26-u11-text-quality-decomposition.md), slice `U11b`.
**Depends on** U11a (`011c56f`), which made `layout_text` iterate **codepoints** rather than
bytes. That dependency is not a nicety here: every break point this slice searches for is an
index into the codepoint vector, so a break can only ever land between characters.

---

## The oracle, named before anything was measured

> **Each line of a multi-line or wrapped block must lay out, in X, exactly as if that line
> had been the whole single-line string** — same `font`, `anchor`, `pos`, `height`, `aspect`,
> `frame`. If line *i*'s quads differ in X from `layout_text(font, <line i's text>, …)`, the
> line is anchored against a width that is not its own, and the block is centred (or
> right-flushed) against a width no line has.

This is the per-line restatement of U11a's whole-string invariant, and it is one assertion
rather than two because it is only satisfiable when the measure pass and the place pass agree
*per line*: a line measured at width `w_m` but placed with total advance `w_p` is anchored at
`centre - w_m/2` and inked over `w_p`, so its glyph X positions move. Anchor::Center is the
sensitive case (the error is halved and signed); Left hides it entirely, which is why the
oracle test is written against Center and Right as well as Left.

**What would falsify the slice:** any line whose quad X values differ from its standalone
layout. **What would NOT falsify it:** differing Y — line *i* sits `i × line_height` lower by
construction, and for a vertically-centred or bottom-anchored block the whole box moves when
the line count changes. The oracle is an X-axis claim on purpose.

---

## The long-word policy — my call, written down rather than left implicit

A "word" with no space in it, longer than the wrap width, has no space to break at. The
parent spec's gate constrains *where* a break may land ("does not wrap mid-character") but
never says whether one happens.

**Decision: force a break at the last codepoint boundary that fits.** Not overflow.

- CSS's default (`overflow-wrap: normal`) overflows, and that was the tempting answer. It is
  the wrong one *here* because **U9b shipped clipping two commits ago**: a label that
  overflows its parent is no longer merely ugly, it is masked, i.e. silently invisible. An
  authored wrap width is the author committing to a box; honouring it except when it matters
  most inverts the contract.
- A forced break also makes the U11a dependency **observable**, which is what gate 1 of the
  parent spec asks for. If a long word simply overflowed, no break would happen at all for
  the no-space case and a per-byte implementation would be indistinguishable from a
  per-codepoint one on that input. Overflow would make the gate vacuous.
- **At least one codepoint is always placed per line**, whatever the width. A codepoint wider
  than the whole wrap width would otherwise produce a zero-length line and a loop that never
  advances.

Declined, and recorded in the backlog in the same turn: hyphenation, an author-selectable
`overflow` vs `break-word` policy, and ellipsis truncation.

## Shape

- `layout_text` gains **one trailing defaulted parameter**, `float wrap_width = 0.0f`, after
  `frame`. `<= 0` means "no wrap", which is every call site that does not opt in — so
  `world_text.hpp:25` is **not touched at all**, and `render_system.hpp` changes only to
  forward a new `UiText` field.
- `wrap_width` is a **fraction of the frame's width**, matching `pos` and `height`, which are
  already frame-fractions. Internally it becomes a maximum advance in atlas pixels, which is
  the unit the break search runs in.
- `\n` is honoured **unconditionally**, wrap width or not. `\r` keeps U11a's silent skip, so
  `"\r\n"` is one break, not two. Every `\n` starts a line, including a trailing one.
- Lines are computed **once**, as `{begin, end, advance}` ranges over the codepoint vector,
  and both the measure result and the place pass read that same vector of ranges. The measure
  pass and the place pass cannot disagree per line because there is only one measurement.
- The block box is anchored once at `{widest line, lines × height}`; each line is then offset
  inside it by `(widest - own width) × f`, `f ∈ {0, ½, 1}` from the anchor's horizontal band.
  That is algebraically identical to anchoring each line independently, and for a single line
  the offset is **exactly** `0.0f`, which is what makes the no-wrap path bit-identical.
- Soft break: the break space is dropped from both lines, as is any run of spaces at the
  break point. A forced break drops nothing.

## Gate 5 — how byte-identity is *proved*, not asserted

Golden quad values for today's authored label strings (`"HP"`, `"MOSAIC"`, plus the mixed
ASCII string the U11a golden test already uses) are **dumped from the pre-change binary** at
`%.9g` and pasted into a permanent test that compares with `==`, not `Approx`. The values
therefore predate the change; passing them after it is evidence, and the two dumps are
diffed as well. Structurally, `wrap_width` defaults to 0 and neither authored label sets it.
